# Motor competitivo

## Principio fundamental

Una recomendación competitiva nunca debe presentarse como una verdad permanente. Debe poder estar vinculada a:

- versión/parche;
- modo;
- mapa;
- rango y subrango;
- tamaño de muestra;
- fecha de actualización.

## Builds

Una build puede definir:

- gadget;
- habilidad estelar;
- refuerzo 1;
- refuerzo 2;
- hipercarga.

Cada elección debe tener **imagen + nombre** en la interfaz.

## Counters

Un counter puede variar según el contexto. La API modela:

- brawler objetivo;
- brawler counter;
- confianza;
- explicación;
- build exacta;
- mapa;
- modo;
- rango;
- parche.

Los datos iniciales de ejemplo no deben confundirse con estadísticas reales. El siguiente paso será sustituir el repositorio temporal por datos versionados y métricas observadas.
